Copying a chart you admire is one of the fastest ways to learn a charting tool. Every detail you notice in the original (a lighter grid line, a legend in an odd place, a gap in the data) becomes a question: which property controls that?

The FT chart above is a good first target. It is a stacked bar chart, the kind of chart Vega-Lite makes by default, but it adds a reference line, a label, a shaded period of missing data and the FT's house style. By the end we will have a chart that is hard to tell apart from the original.

Why the FT chart works

The main quantity (homes built) is shown by position along a common scale, the most accurate channel in Mackinlay's ranking. Sector is a nominal variable, so it gets hue, which Bertin calls selective: you can pick out one sector at a glance. Everything else is kept quiet so the data stands out.

How to use this page

  • Each step shows what changes, the chart it makes, and the full code (click to expand).
  • Use the switch in the sidebar to show code in Vega-Lite (JSON) or Altair (Python). Both produce the same chart.
  • Open any chart in the Vega Editor from its … menu and try changing values. The Altair scripts run as they are in Google Colab.

The steps follow the grammar of graphics: data, then marks and encodings, then scales and guides (axes and legends), then extra layers. Vega-Lite specs are built in the same order, which is why each step only touches one part of the spec.

Step 0Get the data

The FT credits the ONS, so we start there. The dataset is House building, UK: permanent dwellings started and completed. Download the Excel file and open the Contents sheet. The table we want is 3a: dwellings completed by sector, United Kingdom, by calendar year.

In Excel

  1. The FT shows completed homes, so ignore the columns for homes started.
  2. Copy Period and the three Completed sector columns to a new sheet. Leave out the total: the stacked bars add up to it anyway.
  1. Stack the three sector columns on top of each other, so the sheet has three columns: Period, Sector and Completed.
  2. Set the number format of Completed to General, so the CSV has no thousands separators, then save the sheet as CSV.
Why long format?

Vega-Lite maps columns to visual channels. With a single Sector column we can write "color": {"field": "Sector"} and get one colour per sector. In wide format there is no single field to point at.

Or in Python

The same steps in pandas. The full script is prepare_data.py; the key step is melt, which turns wide data into long.

# Table 3a has five rows of notes above the column headings
wide = pd.read_excel(io.BytesIO(response.content), sheet_name="3a", skiprows=5)

wide = wide[["Period", "Completed - Private Enterprise",
             "Completed - Housing Associations", "Completed - Local Authorities"]]
wide.columns = ["Period", "Private enterprise", "Housing associations", "Local authorities"]

# Stack the three sector columns into one 'Sector' column
long = wide.melt(id_vars="Period", var_name="Sector", value_name="Completed")

# ONS marks missing years with '[x2]'. Turn these into blanks so Vega-Lite skips them.
long["Completed"] = pd.to_numeric(long["Completed"], errors="coerce").astype("Int64")
long.to_csv("ons_housebuilding_uk_long.csv", index=False)

Host the file

A chart on a website needs the data at a URL. Commit the CSV to a public GitHub repository, open it, and click Raw. The address of that page is the URL to use.

Data gets revised

The ONS revises recent years and has added 2024 and 2025 since the FT published. This page uses a copy downloaded in 2024 that matches the FT chart. Going further shows the chart with the latest data.

Step 1Start from an example

Few people write a spec from a blank page. Open the simple bar chart from the Vega-Lite example gallery, then make two changes:

  1. Replace the inline values in data with a url pointing to our CSV.
  2. Change the field names in encoding to match our columns: Period on the x-axis and Completed on the y-axis.
{
  "$schema": "https://vega.github.io/schema/vega-lite/v6.json",
  "data": {
    "url": "https://raw.githubusercontent.com/jhellingsdata/jhellingsdata.github.io/main/Data/ONS_UK_housebuilding_long.csv"
  },
  "mark": "bar",
  "encoding": {
    "x": {"field": "Period", "type": "nominal"},
    "y": {"field": "Completed", "type": "quantitative"}
  }
}
import altair as alt

url = "https://raw.githubusercontent.com/jhellingsdata/jhellingsdata.github.io/main/Data/ONS_UK_housebuilding_long.csv"

alt.Chart(url).mark_bar().encode(

    y="Completed:Q",
)

Each year has three rows (one per sector), and Vega-Lite stacks bars by default, so each bar already shows the total. We just can't see the sectors yet.

The chart is also very wide (it's shrunk to fit here). A nominal axis treats each year as a separate category and gives every one its own labelled slot.

Altair shorthand

In Altair, "Period:N" is short for a field called Period with type nominal. The letters stand for nominal (N), ordinal (O), quantitative (Q) and temporal (T). Altair needs the type when the data comes from a URL, because it can't look inside the file.

Step 2Dates and colour

Two changes turn this into a stacked bar chart:

  • Period holds years, so its type should be temporal, not nominal. Vega-Lite then spaces the bars by time and labels the axis with dates.
  • Adding a color channel for Sector splits each bar into its three parts and adds a legend.
"encoding": {
  "x": {"field": "Period", "type": "temporal"},
  "y": {"field": "Completed", "type": "quantitative"},
  "color": {"field": "Sector", "type": "nominal"}
}
.encode(
    x="Period:T",
    y="Completed:Q",
    color="Sector:N",
)

Step 3Size and axes

Size

Right-click the FT chart and choose Inspect. Hovering over the <svg> element shows the whole graphic is 700 × 417 pixels. The grid lines inside it are 649 pixels wide, and the zero line sits 389 pixels below the top.

In Vega-Lite, width and height set the size of the plot area, not the whole graphic. Axes, legend and titles are added around it. So we can use the FT's plot size directly.

"width": 649,
"height": 389,
.properties(width=649, height=389)

Start in 1950

Our data begins in 1949; the FT's chart begins in 1950. A filter transform drops the rows we don't want before anything is drawn.

"transform": [
  {"filter": "utcyear(datum.Period) >= 1950"}
],
.transform_filter("utcyear(datum.Period) >= 1950")
Gotcha: comparing dates with numbers

The obvious filter, datum.Period >= 1950, removes every year before 1971. Because Period is encoded as temporal, Vega-Lite turns it into a date before the filter runs. A date compared with a number becomes milliseconds since 1 January 1970, and every date before 1970 is negative. utcyear() pulls the year back out as a number.

One bar per year, centred on its tick

A temporal axis treats each value as a moment, so Vega-Lite doesn't know how wide a bar should be. Adding "timeUnit": "utcyear" tells it each bar covers a whole year. Three more properties match the FT's layout:

  • "bandPosition": 0 centres each bar on the 1 January tick, rather than filling the space from 1 January to 31 December. This is why the FT's "1950" label sits under the middle of the first bar.
  • "width": {"band": 0.85} makes each bar 85% of a year wide, leaving a gap. (Measured from the FT chart: 14.8 pixels of bar to 2.7 of gap.)
  • "binSpacing": 0 removes the extra 1 pixel gap Vega-Lite adds between time-unit bars, since we've set our own.
"mark": {"type": "bar", "width": {"band": 0.85}, "binSpacing": 0},
"encoding": {
  "x": {
    "field": "Period",
    "type": "temporal",
    "timeUnit": "utcyear",
    "bandPosition": 0,
    ...
.mark_bar(width={"band": 0.85}, binSpacing=0)
.encode(
    x=alt.X("utcyear(Period):T").bandPosition(0)...,
    ...
Why "utc"?

A year like 1950 is read as midnight on 1 January 1950 in UTC. Without utc, Vega-Lite shows dates in the reader's local time zone. For a reader in New York that moment falls on 31 December 1949, so every bar would shift back a year. Using utcyear keeps everyone on the same calendar.

Axes

The FT strips its axes back to the minimum. Using the inspector on a grid line shows its colour: rgb(204, 193, 183), or #ccc1b7.

  • No axis titles. Readers don't need to be told the x-axis shows years, and the subtitle will say what the bars measure. Use "title": null.
  • No vertical grid lines, and light horizontal ones.
  • No y-axis line or ticks, and a slightly longer tick (7 pixels) every ten years on the x-axis.
  • Labels in thousands. labelExpr rewrites each label with an expression, so datum.value / 1000 turns 300000 into 300.
  • A fixed y scale. The FT's axis stops just above the tallest bar, at about 440,000.
"x": {
  ...
  "title": null,
  "axis": {
    "grid": false,
    "tickCount": {"interval": "year", "step": 10},
    "domainColor": "#999189",
    "tickColor": "#999189",
    "tickSize": 7
  }
},
"y": {
  "field": "Completed",
  "type": "quantitative",
  "title": null,
  "scale": {"domain": [0, 440000], "nice": false},
  "axis": {
    "gridColor": "#ccc1b7",
    "domain": false,
    "ticks": false,
    "labelPadding": 7,
    "tickCount": 5,
    "labelExpr": "datum.value / 1000"
  }
}
x=alt.X("utcyear(Period):T")
.bandPosition(0)
.title(None)
.axis(
    grid=False,
    tickCount={"interval": "year", "step": 10},
    domainColor="#999189",
    tickColor="#999189",
    tickSize=7,
),
y=alt.Y("Completed:Q")
.title(None)
.scale(domain=[0, 440000], nice=False)
.axis(
    gridColor="#ccc1b7",
    domain=False,
    ticks=False,
    labelPadding=7,
    tickCount=5,
    labelExpr="datum.value / 1000",
),
Altair's method syntax

Each Vega-Lite property of a channel is also a method in Altair, so settings chain one after another: alt.Y("Completed:Q").title(None).scale(nice=False). This is shorter than the older style of passing objects, such as alt.Y("Completed:Q", scale=alt.Scale(nice=False)), and we use it throughout.

Gotcha: "nice" scales

Vega-Lite rounds scale domains to "nice" numbers, even ones you set yourself. Without "nice": false, our domain of 440,000 quietly becomes 450,000.

Last, Vega-Lite draws a thin border around the plot area by default. It is set in the chart's config, which holds default styles for the whole chart:

"config": {
  "view": {"stroke": "transparent"}
},
.configure_view(stroke="transparent")

Data-ink ratio

Edward Tufte argued that most of the ink in a chart should show data. Each element we removed (axis titles, the border, vertical grid lines, y-axis ticks) carried no information. Notice too that the y-axis starts at zero: we read a bar by its length, so a bar chart that doesn't start at zero misleads.

The Styles panel then lists everything applied to that bar. For a local authorities bar:

Vega-Lite marks have the same opacity and fillOpacity properties as SVG, so we copy both. (Together they make the bars 81% opaque, which lets a little of the background through.)

To give each sector its colour, list the sectors in the colour scale's domain and the colours in the same order in its range. The domain also sets the order of the legend. Without it, sectors are sorted alphabetically.

"mark": {
  "type": "bar",
  ...
  "opacity": 0.9,
  "fillOpacity": 0.9
},
"encoding": {
  ...
  "color": {
    "field": "Sector",
    "type": "nominal",
    "scale": {
      "domain": ["Private enterprise", "Housing associations", "Local authorities"],
      "range": ["#0f5499", "#70dce6", "#ef6590"]
    }
  }
}
sectors = ["Private enterprise", "Housing associations", "Local authorities"]
colours = ["#0f5499", "#70dce6", "#ef6590"]

...
.mark_bar(width={"band": 0.85}, binSpacing=0, opacity=0.9, fillOpacity=0.9)
.encode(
    ...
    color=alt.Color("Sector:N").scale(domain=sectors, range=colours),
)

Step 5Legend and stack order

Legend

Legend settings live in a legend object inside the color channel. The FT's legend sits above the chart, in a single column, with no title and wide rectangular swatches.

  • "orient": "top" and "direction": "vertical" place it.
  • symbolType accepts any SVG path as well as named shapes. The path M-1.8,-1H1.8V1H-1.8Z draws a rectangle 1.8 times as wide as it is tall.
"color": {
  ...
  "legend": {
    "orient": "top",
    "direction": "vertical",
    "title": null,
    "symbolType": "M-1.8,-1H1.8V1H-1.8Z",
    "symbolSize": 120,
    "labelFontSize": 16,
    "labelColor": "#33302e"
  }
}
color=alt.Color("Sector:N")
.scale(domain=sectors, range=colours)
.legend(
    orient="top",
    direction="vertical",
    title=None,
    symbolType="M-1.8,-1H1.8V1H-1.8Z",
    symbolSize=120,
    labelFontSize=16,
    labelColor="#33302e",
),

Stack order

By default, Vega-Lite stacks the segments in legend order, from the top down: private enterprise sits on top of each bar. The FT does the reverse, with private enterprise at the base, so the largest sector rests on the axis.

The order channel controls stacking, but it can only sort a field up or down. Our order isn't alphabetical either way, so we make a field that holds it. A calculate transform looks up each sector's position in our list (0, 1 or 2) with indexof, and the bars stack from 0 upwards.

"transform": [
  {"filter": "utcyear(datum.Period) >= 1950"},
  {
    "calculate": "indexof(['Private enterprise', 'Housing associations', 'Local authorities'], datum.Sector)",
    "as": "SectorOrder"
  }
],
...
"encoding": {
  ...
  "order": {"field": "SectorOrder", "type": "quantitative"}
}
.transform_calculate(SectorOrder=f"indexof({sectors}, datum.Sector)")
...
.encode(
    ...
    order="SectorOrder:Q",
)
Gotcha: Altair shorthand in JSON

You may see "order": {"field": "max(Completed)"} suggested for this. In a Vega-Lite spec, max(Completed) is read as the name of a column, and there is no such column. The chart only looks right because, with nothing to sort on, Vega-Lite falls back to the order of rows in the CSV, which happens to match. Shorthand such as max(Completed) is an Altair feature. In JSON, aggregation goes in its own "aggregate" property.

Step 6Layers: the target line

So far the chart has one mark: bars. The FT chart has four kinds of element:

  1. stacked bars (bar mark)
  2. a dashed line at 300,000 (rule mark)
  3. the "Labour target" label (text mark)
  4. a shaded block over the missing years (rect mark)

To combine marks, we use a layered spec. Properties shared by every layer (size, background, config) stay at the top. Each layer gets its own mark and encoding. Layers are drawn in order, so later layers sit on top.

{
  "$schema": "https://vega.github.io/schema/vega-lite/v6.json",
  "data": {...},
  "transform": [...],
  "width": 649,
  "height": 389,
  "background": "#fff1e5",
  "config": {...},
  "layer": [
    {"mark": {...}, "encoding": {...}},   // the bars, moved here unchanged
    {...}                                 // the target line and its label
  ]
}
# In Altair, build each layer as its own chart...
bars = alt.Chart(url).mark_bar(...).encode(...)

# ...then combine them. Shared properties go on the layered chart.
chart = (
    alt.layer(bars, rule, label)
    .properties(width=649, height=389, background="#fff1e5")
    .configure_view(stroke="transparent")
)

The target line and label

The target isn't in our CSV, so this layer brings its own data: a single row with target: 300000. A rule with only a y encoding draws a horizontal line across the full width.

The label uses the same data and the same y, so we nest a second layer inside: shared data and encoding go on the outside, and each inner layer adds a mark.

  • A list of strings, ["Labour", "target"], puts each item on its own line.
  • "x": {"expr": "width / 2"} centres the label horizontally, using the chart's width.
  • dy lifts it above the line. Text is centred on its position, and the second line sits one line height (17 pixels) below the first, so it takes 30 pixels to clear the line with a small gap.
{
  "data": {"values": [{"target": 300000}]},
  "encoding": {"y": {"field": "target", "type": "quantitative"}},
  "layer": [
    {"mark": {"type": "rule", "strokeDash": [6, 4], "strokeWidth": 2.2, "color": "#33302e"}},
    {
      "mark": {
        "type": "text",
        "text": ["Labour", "target"],
        "x": {"expr": "width / 2"},
        "dy": -30,
        "lineHeight": 17,
        "fontSize": 14.4,
        "fontWeight": 600,
        "color": "#33302e"
      }
    }
  ]
}
target = alt.Chart(alt.Data(values=[{"target": 300000}])).encode(y="target:Q")
rule = target.mark_rule(strokeDash=[6, 4], strokeWidth=2.2, color="#33302e")
label = target.mark_text(
    text=["Labour", "target"],
    x=alt.expr("width / 2"),
    dy=-30,
    lineHeight=17,
    fontSize=14.4,
    fontWeight=600,
    color="#33302e",
)
Layers with their own data

A layer with its own data ignores the top-level data and the top-level transforms. So our 1950 filter doesn't touch the target row, which is what we want.

Step 7Missing years

Covid disrupted data collection, so there are no figures for 2020 to 2022. Vega-Lite already leaves those years blank, because it skips empty values. The FT goes further and shades the gap, so readers know the data is missing rather than zero.

The inspector shows the FT draws a <rect> filled with a diagonal hatching pattern at 20% opacity:

A rect layer with x and x2 but no y fills the full height of the chart. Since our bars are centred on 1 January, the gap runs from halfway between 2019 and 2020 (1 July 2019) to halfway between 2022 and 2023 (1 July 2022). We add the layer first, so it sits behind the bars and the target line.

"layer": [
  {
    "data": {"values": [{"start": "2019-07-01", "end": "2022-07-01"}]},
    "mark": {"type": "rect", "color": "#ccc1b7", "opacity": 0.5},
    "encoding": {
      "x": {"field": "start", "type": "temporal"},
      "x2": {"field": "end"}
    }
  },
  {...},   // bars
  {...}    // target line and label
]
gap = (
    alt.Chart(alt.Data(values=[{"start": "2019-07-01", "end": "2022-07-01"}]))
    .mark_rect(color="#ccc1b7", opacity=0.5)
    .encode(x="start:T", x2="end")
)

chart = alt.layer(gap, bars, rule, label)

Vega-Lite has no pattern fills, so we use a flat tint. Going further shows how to add real hatching on a web page.

Step 8Titles and font

Title and subtitle

The FT's headline states the finding, not the topic, and the subtitle names the measure and its units. "anchor": "start" left-aligns both.

"title": {
  "text": "The UK has not built 300,000 homes a year since 1977",
  "subtitle": "Completed dwellings (000)",
  "anchor": "start",
  "offset": 16,
  "fontSize": 21,
  "fontWeight": "normal",
  "color": "#33302e",
  "subtitleFontSize": 16,
  "subtitleColor": "#4d4845",
  "subtitlePadding": 8
},
.properties(

        color="#33302e",

Source note

Vega-Lite has one title, which can go at the top or the bottom but not both. We could borrow the x-axis title for the source, but then a chart that needs an axis title couldn't have both. A text layer works for any chart. It goes last in the layer list.

  • One row of data. A layer without its own data uses the CSV, and would draw the note once per row: 231 copies on top of each other. A single empty row, [{}], draws it once.
  • Two lines. As with the target label, a list of strings puts each on its own line. The first line credits the FT, where the original has "©FT".
  • Placed with an expression. height is the height of the plot, so "y": {"expr": "height + 40"} keeps the note 40 pixels below it. If you change the chart's height, the note moves with it. With "baseline": "top", the 40 pixels are measured to the top of the text.
  • Lined up on the left. "x": -31 with "align": "left" starts the text at the left edge of the y-axis labels.
{
  "data": {"values": [{}]},
  "mark": {
    "type": "text",
    "text": [
      "Recreated from an FT chart",
      "Source: ONS • Covid affected data collection between 2020 and 2022"
    ],
    "x": -31,
    "y": {"expr": "height + 40"},
    "align": "left",
    "baseline": "top",
    "lineHeight": 17,
    "fontSize": 13,
    "color": "#4d4845"
  }
}
source = alt.Chart(alt.Data(values=[{}])).mark_text(
    text=[
        "Recreated from an FT chart",
        "Source: ONS • Covid affected data collection between 2020 and 2022",
    ],
    x=-31,
    y=alt.expr("height + 40"),
    align="left",
    baseline="top",
    lineHeight=17,
    fontSize=13,
    color="#4d4845",
)

chart = alt.layer(gap, bars, rule, label, source)
Marks outside the plot

The note sits below the plot area, but nothing is cut off. Vega-Lite grows the chart to fit every mark, so the padding around the chart adjusts on its own.

Font

The inspector shows the FT uses Metric, a typeface licensed to the FT. We can't use it, but we can pick a free font with a similar feel. Hanken Grotesk from Google Fonts is a close match: narrow, with similar numbers. Set it once in config and every piece of text uses it. Axis label sizes come from the FT's SVG (font-size="14.4").

"config": {
  "view": {"stroke": "transparent"},
  "font": "Hanken Grotesk, Arial, sans-serif",
  "axis": {"labelColor": "#4d4845", "labelFontSize": 14.4}
},
.configure(font="Hanken Grotesk, Arial, sans-serif")
.configure_view(stroke="transparent")
.configure_axis(labelColor="#4d4845", labelFontSize=14.4)
The font must be loaded

A chart can only use a font the browser has. On your site, load it with a <link> from Google Fonts, and wait for it before drawing the chart (see Put it on your site). In Colab and the Vega Editor, the chart falls back to Arial.

Line everything up

In the FT chart the title, legend, y-axis labels and source note all share one left edge. A legend with "orient": "top" lines up with the plot instead, about 31 pixels to the right. Setting "orient": "none" lets us place the legend by hand, relative to the top left corner of the plot.

"legend": {
  "orient": "none",
  "legendX": -31,
  "legendY": -75,
  "rowPadding": 0,
  ...
}
.legend(
    orient="none",
    legendX=-31,
    legendY=-75,
    rowPadding=0,
    ...
)

Step 9Finishing touches

Two small changes. First, the FT separates the segments of each bar with a thin gap, which makes the small local authority slivers easier to see. A stroke in the background colour does the same. A stroke is drawn on the edge of a shape, half inside it, so it also trims the sides of each bar. We widen the bars to 95% of a year to make up for it.

Second, a tooltip shows the exact figure when you hover over a bar. The format adds thousands separators.

"mark": {
  "type": "bar",
  "width": {"band": 0.95},
  "binSpacing": 0,
  "opacity": 0.9,
  "fillOpacity": 0.9,
  "stroke": "#fff1e5",
  "strokeWidth": 1
},
"encoding": {
  ...
  "tooltip": [

Step 10Click to hide a sector

On the FT site, clicking a sector in the legend removes its bars, and the other sectors drop down to fill the gap. The legend entry fades, and clicking it again brings the sector back. (The FT also animates the bars falling away. Vega-Lite can't animate changes, so ours jump.)

Interaction in Vega-Lite starts with a parameter that holds a selection. Ours is a point selection on the Sector field, with three settings:

  • "bind": "legend": clicks on the legend make the selection, instead of clicks on the bars.
  • "toggle": "true": each click adds or removes one sector, rather than replacing the whole selection.
  • "value": the selection starts with all three sectors, so every bar shows.

The selection holds the sectors that are shown. A filter transform then keeps only rows in the selection. "empty": false means that if the reader hides every sector, the chart shows no bars rather than all of them.

{
  "params": [
    {
      "name": "shown",
      "select": {"type": "point", "fields": ["Sector"], "toggle": "true"},
      "bind": "legend",
      "value": [
        {"Sector": "Private enterprise"},
        {"Sector": "Housing associations"},
        {"Sector": "Local authorities"}
      ]
    }
  ],
  "transform": [{"filter": {"param": "shown", "empty": false}}],
  "mark": {...},       // the bar layer, unchanged
  "encoding": {...}
}
shown = alt.selection_point(
    fields=["Sector"],
    bind="legend",
    toggle="true",
    value=[{"Sector": sector} for sector in sectors],
    empty=False,
)

bars = (
    alt.Chart(url)
    ...
    .add_params(shown)
    .transform_filter(shown)
    .mark_bar(...)
    .encode(...)
)
Why select the shown sectors, not the hidden ones?

When a selection is bound to a legend, Vega-Lite fades every entry that is not selected. So the selection has to hold the visible sectors: hidden ones then fade, as on the FT site. The one oddity is that with all three hidden the selection is empty, and Vega-Lite shows an empty selection as "nothing chosen", with every entry at full strength.

Step 10 result: click the legendView on GitHub

The y-axis stays fixed at 0 to 440,000 while sectors come and go. That keeps the scale honest: the remaining bars visibly shrink, rather than the axis stretching to fill the space.

Real hatching with an SVG pattern

Vega-Lite can't draw patterns, but on a web page we can borrow one. Define an SVG <pattern> anywhere in the page, then set the rectangle's fill to url(#id). This only works with Vega's SVG renderer (vegaEmbed(el, spec, {renderer: "svg"})), and only on a page that contains the pattern. In the Vega Editor or Colab, the rectangle won't show.

An FT-style tooltip

The FT's tooltip has two lines: the sector, in the colour of its bar, then the year in bold and the value in thousands. Our tooltip from step 9 is a table of field names and values.

Within Vega-Lite, the closest we can get is the mark's tooltip property with an expression. It builds one string, and \n starts a new line, but the text can't be styled:

"tooltip": {
  "expr": "datum.Sector + '\\n' + utcyear(datum.Period) + ': ' + format(datum.Completed, ',')"
}
.mark_bar(
    ...,
    tooltip=alt.expr("datum.Sector + '\\n' + utcyear(datum.Period) + ': ' + format(datum.Completed, ',')"),
)

For colour and bold text we go one level down, to the web page. Tooltips are drawn by the vega-tooltip library inside vegaEmbed, and it takes two useful options:

  • formatTooltip is a function that receives the tooltip's values (keyed by the titles from step 9: Year, Sector, Completed) and returns HTML. sanitize escapes each value, so stray HTML in the data can't break the page.
  • theme adds a class (here ft-theme) to the tooltip, so we can style it with CSS.

The spec doesn't change. Keep the step 9 tooltip encoding and pass the options to vegaEmbed. The values arrive already formatted as text ("143,720"), so to show thousands we remove the commas, turn the text back into a number and divide.

const colours = {
  "Private enterprise": "#0f5499",
  "Housing associations": "#70dce6",
  "Local authorities": "#ef6590",
};

// "143,720" -> 144
const thousands = (text) => Math.round(Number(text.replace(/,/g, "")) / 1000);

vegaEmbed("#housebuilding", "ft_housebuilding.json", {
  tooltip: {
    theme: "ft",
    formatTooltip: (value, sanitize) =>
      `<div class="sector" style="color: ${colours[value.Sector]}">${sanitize(value.Sector)}</div>` +
      `<b>${sanitize(value.Year)}:</b> ${thousands(value.Completed)}`,
  },
});
#vg-tooltip-element.ft-theme {
  font-family: "Hanken Grotesk", sans-serif;
  font-size: 16px;
  line-height: 1.35;
  color: #33302e;
  background: #fff;
  border: none;
  border-radius: 6px;
  padding: 8px 12px;
  box-shadow: 0 2px 8px rgba(0, 0, 0, 0.18);
}

#vg-tooltip-element.ft-theme .sector {
  font-weight: 600;
}
With an FT-style tooltip: hover over a bar
Colour as text

Hover over a housing associations bar: the pale teal is hard to read as text on white (a contrast ratio of about 1.6:1, against the 4.5:1 that accessibility guidelines ask for), and the pink only reaches 3:1. A colour that works for a bar doesn't always work for words. A small coloured square beside a dark label is a safer choice.
